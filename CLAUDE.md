# zatgo-core

Custom Frappe app extending ERPNext for ZatGo's Van Sales / Accounting / Inventory platform. See `../CLAUDE.md` (Frappe/ERPNext category) and `../../.claude/rules/` (git, testing, accounting, architecture, security) for everything not specific to this repo.

## Repo-specific pointers

- Idempotent-insert helper: `zatgo_core/services/idempotency.py::insert_idempotent`. Use it for any new create-endpoint keyed on `zatgo_client_id` rather than re-deriving the check-then-insert pattern.
- Custom-field self-healing: `zatgo_core/setup/ensure_custom_fields.py`, called from `install.py`'s `after_install`/`after_migrate`. If you add a new schema-critical custom field, register it there too, not only in a `patches.txt` entry.
- VanSaleX (mobile van sales) settings: Desk workspace "VanSaleX" + config-center manifest `plugins/manifests/vansalex.py`. `VanSaleX Settings` (single) + per-user `ZG Van Sale Profile` overrides are resolved by `services/vansalex_settings.py` (`resolve`, `resolve_sale`, `allowed_warehouse`) — the one place warehouse / Cash-Credit / cash-account rules live; APIs and the app both go through it. Defaults come from ERPNext first (Mode of Payment "Cash" account, Stock Settings), zatgo_core second. A missing `payment_type` on `orders.create`/`confirm` deliberately keeps pre-Cash/Credit behaviour (older app builds).
- VanSaleX modules & features (which parts of the app a client/site and user get): `services/vansalex_access.py` — `VanSaleX Settings.access` rows + profile switch-offs, delivered in `me.context.access`, enforced in every `api/v1/vansalex/*` endpoint and a field-user DocType backstop (Stock Entry, Payment Entry Pay/Internal Transfer and the sales feature switches too). New VanSaleX functionality gets a catalog key (default off). A field user's stock transfers / write-offs / opening stock follow `services/vansalex_stock_rules.py` (`inventory.transfer` / `inventory.adjust`, Warehouse "VanSaleX Transfer Point"); a vansalex service that builds a Sales Invoice/Order after its own checks calls `mark_api_validated(doc)` so the backstop doesn't repeat them. `ensure_vansale_perms` seeds each DocPerm once, then leaves it to the admin. See `docs/vansalex_access.md`.
- Sales Invoice naming series: chosen only by the Sales Invoice `before_insert` hook (`events/sales_invoice_naming.py` → `services/sales_invoice_naming.py`), from the session user's rule in `ZG Sales Invoice Naming Settings` (user + company → invoice / return series), else ERPNext's default plus the generic `-RET-` switch (`events/return_naming.py`). Don't pick `naming_series` in API/service code (for a user with a rule the hook overwrites it). This replaced the old `ZG Van Sale Profile` series fields.
- Multi-method / multi-account payments: `services/payment_allocation.py` + `overrides/` (`extend_doctype_class` mixins — hrms already overrides Payment Entry's class). Sales Invoice uses ERPNext's own POS `payments` table (ERPNext posts the GL); Payment Entry splits only its bank-side GL line across `custom_payment_details`. Allowed accounts per method/company: Mode of Payment `custom_zg_accounts`. After deploying, `bench clear-cache` — the mixins are cached with the hooks. See `docs/multi_payment.md`.
- Integration tests live in `zatgo_core/tests/integration/` (money-path, returns, idempotency) — extend these for new financial-document endpoints rather than relying on unit tests alone.
- Merged-in apps (2026-10-08), all switched per site in ZG System Settings and off unless switched on:
  - UI (`services/ui_apps.py`): SaaS Desk theme + login page (`page_renderer`; theme CSS is generated from `public/saas_theme/css/src/*.css` — edit the partials and run `scripts/build_saas_theme.py`, see `docs/saas_theme.md`), EN/AR language switcher (`api/v1/language.py`), VanSaleX web page `/vansalex` (`www/vansalex.py`; build via `scripts/deploy_web_build.sh`). Desk JS/CSS are added per request by a `before_request` hook — never use `app_include_css/js` in hooks.py for site-optional assets, they load on every site.
  - Modules with DocTypes (`services/bundled_apps.py`): `chat_ai/`, `tracker/`, `zatgo_space/`. Every hook goes through a gated wrapper there; their setup lives in `<module>/install.py::bootstrap` and their workspace/sidebar JSON in `<module>/desk_records/` (deliberately outside Frappe's synced folders). A new hook for one of them must be a wrapper in `bundled_apps.py` that returns at once when switched off. A new module registers itself via `app_manifest.py` (see ZatGo Apps below).
- **MyBis** (`mybis/`, `api/v1/mybis/`, `services/mybis/`, switch `enable_mybis`, off by default): the read-only management/BI API behind `mobile/mybis`. Endpoints are thin and go through `api/v1/mybis/_common.run` (scope -> `queries.guard` -> cache -> envelope); SQL lives only in `services/mybis` (`tests/unit/test_mybis_sql_safety.py` lists every text interpolated into SQL -- a new one fails until reviewed); statements and aging reuse ERPNext's reports. Users with User Permissions other than Company are refused, since raw SQL cannot apply them. `tests/integration/test_mybis_security.py` discovers endpoints itself (login, GET/POST only, no-rights user, 404 when off), so a new one is covered without editing it. Definitions and API: `docs/mybis.md`.
- **ZatGo Apps** (Desk page `zg-app-hub`, System Manager; formerly "App Settings Hub"): the one place to switch and reach the settings of every app. One catalog drives everything -- `services/app_catalog.py` (manifest keys documented in its docstring; each module folder ships `<module>/app_manifest.py`, core entries are in `plugins/manifests/core_apps.py`). `services/app_state.py` answers "is app X on" (the **only** reader of the switches; `ui_apps.switches` re-exports it), `services/app_gate.py` is the server-side gate (API prefixes -> 404, `@app_api`, `require_app`), `services/app_authority.py` makes switching **System Manager only in the ZG System Settings controller** (the form and REST are bound, not just the hub), `services/app_desk.py` hides/shows the Desk entries of in-core apps. **A new bundled module needs its `app_manifest.py`** (switch field, API gate, hub card, sidebar, registry all follow); still manual: the gated hook wrappers in `bundled_apps.py` / `hooks.py` and its `bootstrap`. See `docs/plugin_guide.md` (the contract) and `docs/naming.md` (new DocTypes are `ZG <Name>`; 25 legacy names kept, enforced by `tests/unit/test_naming_standard.py`).
- **VanSaleX is a switchable app** (`enable_vansalex`, ZG System Settings -> Apps, group `app`, `default_on`): a site with no stored value counts as ON -- `app_state` reads `tabSingles` itself for such apps because a Check on a Single reads 0 both for "stored 0" and "nothing stored". Any other app that gains a switch after it was always on needs `default_on` + a patch that stores 1 (`patches/v0_4_7`). Off = `zatgo_core.api.v1.vansalex.*` answers 404, leaves the sidebar, its workspace is hidden (not deleted: it is a synced file; every app's rail icon is always hidden); shared accounting/warehouse endpoints stay up; `/vansalex` web page follows (`vansalex_web` `requires` it).
- **ZatGo POS is a switchable app like VanSaleX** (`enable_zatgo_pos`, `default_on`, group `app`): settings = single `ZG POS Settings` (tabs General / Payments / Receipt & Printing; every tab a Tab Break), workspace `ZatGo POS`, delivered to the desktop POS by `api/v1/pos_settings.get` (`services/pos_settings.py`; `@app_api("zatgo_pos")`). Off = `zatgo_core.api.v1.resto_pos.*` answers 404; `pos_profile` / `pos_settings` sit outside that prefix. The desktop POS (`desktop/zatgo-pos`) does not read `pos_settings` yet -- the values are served, not yet consumed. Patch `v0_4_9` stores the default-on 1.
- **Plugin registry is a projection of the catalog** (`plugins/discover.py`, run on migrate and whenever a switch changes): real `enabled`/`version`; an admin's edit of `visible`/`roles`/`menu_order` survives (three-way compare against the previously registered manifest), `enabled` follows the switch; a re-run changes nothing and writes no history. `ZG Registered Application.category` is a Select (`Platform` / `Other` for catalog rows).
- Chat AI tool calls (REST tools, MCP, connectors, health checks) go through `chat_ai/core/tool_sources/net.py` -- never `urllib.request.urlopen` directly (`tests/test_tool_network.py` fails if a tool source does). API reads that cannot use `frappe.get_list` use `services/row_scope.py` (Company User Permission in SQL, portal party scope, permission-aware `count`); `get_all`/`db.count` skip User Permissions.
- `ZG Device Token` / `ZG User Preferences` are owner-scoped on every route (`permissions/owner_scope.py`); `settings.save_settings` accepts only ZatGo settings DocTypes and ignores a caller-supplied `category`.
- **The "ZatGo" Desk sidebar is generated** (`services/core_sidebar.py`, synced by `ensure_core_desk` on migrate and at the end of `ZGSystemSettings.on_update`, so flipping a switch in the hub updates it at once): two sections. **Apps**: one `child=1` entry per enabled app (catalog groups `app`/`bundled`, then enabled industries), each a link to the app's Workspace (so who sees it is still the Workspace's roles; an app without a Workspace falls back to its first settings DocType). **General Settings**: the switch-only apps (Desk theme / language switcher / VanSaleX web -> the hub), then the hub, then the general `workspace/zatgo/zatgo.json` shortcuts -- never an app's own settings (those are tabs of its page). The hub entry must come AFTER the switch-only ones: Frappe highlights the last item whose path matches the open page. Frappe nests one level only (every row after a section is `child=1`; a top-level row after a section would look like part of it). Don't edit the sidebar by hand or by adding to `zatgo.json` for an app -- add `app_manifest.py`. App display names carry the "ZatGo" prefix (ZatGo AI, ZatGo Tracker, ...). Compact left-aligned Desk layout: `public/saas_theme/css/src/31-layout-compact.css` (`--page-max-width: 100%` + tight `--zg-layout-*` spacing; theme-on sites only).
- **App pages with tabs** (`/desk/zg-app/<route key>`, the route key = slug of the app's label, e.g. `zatgo-vansalex` -- never the bare key: for a two-part route Frappe opens a sidebar named like the second part, and the auto module sidebar "Tracker" would beat ZatGo's; Page `zg-app`, `services/app_page.py`, `api/v1/app_page.py::get_app_page`): an Apps entry stays a Workspace link but `events/boot.py::_route_sidebar_entries` sets its `route` (Frappe's sidebar navigates to `item.route`; Frappe never fills it) to the page. Tabs = "Overview" (the Workspace's shortcuts and cards, each link filtered by `frappe.desk.desktop.Workspace.is_item_allowed`) + one tab per **Tab Break** of the app's settings DocType (read from the DocType: a new Tab Break is a new tab with no other edit; every settings DocType must start with a Tab Break). A settings tab opens that form on its tab; `public/js/zg_app_tabs.js` (always loaded) puts an "Overview" tab back in front of the form's bar. A form cannot be embedded in a page, hence two screens with one bar. The page calls `frappe.app.sidebar.setup("ZatGo")` itself: opened directly (reload) Frappe builds no sidebar. Every app's own rail icon is hidden (`app_desk.sync_rail_icons`, never the Workspace); old `/desk/zatgo-vansalex`-style URLs redirect via `zg_route_redirects.js` (`frappe.boot.zatgo_core.app_routes`). Editing a settings DocType JSON: bump its `modified` or migrate skips it.
- **Source Warehouse auto-fill is a setting** (ZG System Settings -> "Auto-fill Source Warehouse on Documents", default on): `events/default_source_warehouse.py::autofill_enabled` gates both the form (`get_default_source_warehouse`, called by `public/js/default_source_warehouse.js`) and the `before_validate` hook, so off means blank in the form AND on save. No row = on (existing sites keep filling); patch v0_4_5 stores the 1 so the form shows what is enforced -- any ZG System Settings checkbox that is on by default needs such a patch, or the form opens it unticked and a save silently turns it off. VanSaleX sales flows set `set_warehouse` themselves and do not depend on the fill.
- **Payment Entry account from the chart** (ZG System Settings -> "Auto-fill Account Paid To / Paid From on Payment Entry", default on): `services/payment_entry_accounts.py`. Ticked: a *Bank* mode of payment fills Account Paid To (Receive) / Paid From (Pay) with the mode's default (if it is a valid Bank Accounts ledger), else `Company.default_bank_account`, else the first ledger under the chart's "Bank Accounts" group (any ledger of Account Type Bank or under a Bank-type group -- same definition as the invoice Cash/Bank pickers, `chart_ledgers`), and the picker offers only those; other modes keep ERPNext's default and list. Unticked: blank (every mode) and ERPNext's own list. Form side (`public/js/payment_entry.js`): ERPNext's mode_of_payment handler goes through `erpnext.accounts.pos.get_payment_mode_account` (shared with POS rows), wrapped for Payment Entry only so the field has one source; ERPNext's paid_to/paid_from queries are wrapped in `refresh` (after its `setup`). Patch v0_4_6 stores the 1 (same unticked-form trap as v0_4_5). Server-side saves are unchanged: blank + mandatory means the user must pick.
- **App names on Desk are "ZatGo ..."** -- Workspace, Workspace Sidebar and Desktop Icon of an app carry one name: `ZatGo AI`, `ZatGo Tracker`, `ZatGo VanSaleX` (+ industries `ZatGo <Label>`); Frappe v16 needs icon label == sidebar name. A site that still has the old names (`AI Admin`/`Chat AI`, `Tracker`/`Task Management`, `VanSaleX`) is migrated by `<module>/install.py` (`_adopt_desk_name` / `_adopt_workspace`: rename, or delete the legacy record when the shipped JSON already created the new one) and `setup/ensure_core_desk._retire_legacy_workspaces` (also renames the old rail entry -- the Workspace Sidebar + Desktop Icon created with the old workspace, e.g. a separate "VanSaleX" rail icon -- and repoints its links, even when migrate's orphan purge already deleted the old Workspace); `app_manifest.workspaces` lists the new name first and keeps the old ones so `remove_desk_entries` still cleans them. A synced workspace file must sit at `workspace/<scrub(name)>/<scrub(name)>.json` (`zatgo_vansalex/`). Old Desk URLs (`/desk/tracker`, `/desk/ai-admin`, `/desk/vansalex`) redirect via `public/js/zg_route_redirects.js` (always loaded, `frappe.re_route`) -- add a line there whenever an app is renamed again.
- **ZatGo AI is local-only by default** (`chat_ai/core/providers/local_guard.py`): Chat AI Settings -> "Local models only" is ON unless explicitly unticked. `registry.from_settings` refuses any model / embedding endpoint outside the private network (loopback, RFC1918, bare container names, `*.local`/`*.internal`/`*.lan`, or a name that resolves only to private IPs) before any request is made; saving the settings, Brave search and an external SearXNG are refused too. Default provider is Ollama (`http://127.0.0.1:11434/v1`, model `llama3.2`, embeddings `nomic-embed-text`). One-call setup: `bench --site X execute zatgo_core.chat_ai.setup_self_hosted.configure_ollama --kwargs '{"ollama_url": "http://ollama:11434"}'`; probe with `...setup_self_hosted.check` (Ollama has no /health -- it reads /api/tags and reports unpulled models). `context_window_tokens` (default 4096) must not exceed Ollama's real context (`OLLAMA_CONTEXT_LENGTH`). A site that uses an external API must untick the switch explicitly -- on upgrade, a site with an external provider configured is refused until then. Live test against a real Ollama: `tests/test_ollama_live.py` (skips when none is reachable). Install/migrate saves of the settings set `doc.flags.ignore_local_only`.
- Deploying a change to `modules.txt`: run `bench --site X clear-cache` **before** `migrate` — migrate syncs DocTypes only for modules in the cached module map and silently skips new ones. Module Defs are created by `install-app` only; `ensure_ui_apps` creates the bundled ones on migrate.
- Industries (`zatgo_core/industries/`, `docs/industries.md`): registry + per-site switch in ZG System Settings → Industries; server-side gating in `industries/gate.py` (API 404, `"*"` permission hooks, `@industry_api`). Resto POS is the Restaurant industry (auto-enabled on upgrade where it holds data). New industry = registry entry + package + tests; public Workspaces made in code must not carry both `module` and `app` (migrate deletes them as orphans).
