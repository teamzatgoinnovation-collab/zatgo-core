# SaaS Desk theme

Optional Desk theme + login page, switched per site in **ZG System Settings → Desk Appearance → Enable SaaS Theme** (`enable_saas_theme`). Loaded per request by `services/ui_apps.py::add_desk_includes` — never via `app_include_css/js` in `hooks.py`. The standalone `erpnext/saas_theme` repo is archived; change the theme here.

## Files

```
zatgo_core/public/saas_theme/
├── css/
│   ├── src/*.css          ← EDIT THESE (ordered partials)
│   ├── saas_theme.css     ← GENERATED by scripts/build_saas_theme.py (committed; served)
│   └── login.css          ← login page (standalone; loaded without Desk's bundle)
└── js/saas_theme.js       ← workspace rail, user menu, attachment cards, mobile nav drawer
```

The served file is one content-hashed URL, and the bench has no asset pipeline for it, so the partials are concatenated by a small script and the result is committed.

```bash
python3 scripts/build_saas_theme.py          # write css/saas_theme.css
python3 scripts/build_saas_theme.py --check  # exit 1 if stale (also a unit test: tests/unit/test_saas_theme_build.py)
```

After deploying, restart the web worker: the asset hash is cached per process (`ui_apps.asset_url`).

## Rules for changing it

- **Tokens, not literals.** Colours/spacing/radius/shadow come from Frappe's variables (themed in 00/01) or `--zg-*`. A colour that differs between light and dark is defined once in `02-tokens-semantic` and swapped there — don't write a second `[data-theme="dark"]` rule.
- **No `!important` by default.** The theme loads after Frappe's bundle, so equal specificity wins. Where Frappe is more specific, add a real ancestor class. Use `!important` only for inline styles / unmatched Frappe specificity and comment why. (482 → ~130 in the first pass; the remainder sit in `:hover`/media/pseudo contexts or fight Frappe's `.btn`.)
- **Check selectors against Frappe v16** (`apps/frappe/frappe/public/scss`, the compiled `sites/assets/frappe/dist/css/desk.bundle.*.css`, `public/js/frappe/ui`) — a class Frappe never emits is dead code.
- Dark mode = `[data-theme="dark"]` on `<html>`; the rail is always dark by design.
- Motion is handled globally (`90`): use `--zg-duration-*`, never `transition: all`.

## Verifying a CSS change without eyeballing

Visual regressions hide in states a page doesn't show by default. The method used for the `!important` and token passes:

1. Put the candidate build next to the live file (e.g. `css/candidate.css` in the bench's `public/`, not committed).
2. In the browser console, snapshot `getComputedStyle` (colour, border, radius, shadow, padding, margin, font, display, size…) of every element with the live stylesheet, swap the `<link>` href to the candidate, snapshot again, and diff — in light **and** dark, on: list view (with a dialog + menu open), a saved form **with** tags, attachments, an assignment, a comment and a share, a User form (every tab), a workspace with number cards/charts, report view, `/desk` with the rail collapsed and expanded.
3. Zero diff = pure refactor. Any diff must be intentional.

Hover/focus/pseudo-element states are not captured by a computed-style snapshot — check those by hand.

## Known limits

- `login.css` keeps its own `--st-login-*` brand tokens (it loads without the Desk bundle) and ~87 `!important` — the website bundle's cascade differs and most are needed in dark mode. Keep the brand hex in sync by hand (see the header comment).
- **Fonts**: Poppins for all text, served from `public/saas_theme/fonts/poppins/` (no font CDN; `OFL.txt` ships with the files). Poppins has no tabular figures and the theme aligns amounts with `font-variant-numeric: tabular-nums`, so the first family, `ZG Digits`, is Inter's variable font (Frappe ships it at `/assets/frappe/css/fonts/inter/`) restricted by `unicode-range` to 0-9: digits are Inter, every other glyph Poppins. Arabic is **Cairo** (Arabic subset, 400/500/600/700, `fonts/cairo/`, SIL OFL), placed right after Poppins in the stack: Poppins is Latin-only, so Arabic letters and Arabic-Indic digits fall to Cairo; only characters neither covers reach the system fonts. `css/login.css` carries its own copy of the `@font-face` blocks (the login page does not load `saas_theme.css`) -- keep both in step. A deploy must copy `fonts/` (poppins and cairo) into `erpnext-frontend-1`'s `assets/zatgo_core/saas_theme/` too (nginx serves assets from the frontend container).
- Accent hues cycle by position, so an icon's colour changes if the list around it changes. A stable per-workspace hue would need a small JS addition (hash the label into a `data-hue`).
- The Color field's picker icon overlaps its placeholder (pre-existing, also in the old stylesheet).
- Frappe marks no destructive menu item; `.dropdown-item.text-danger` is styled as an opt-in hook but no stock item carries it.
- The partials in 82–87 were checked against Frappe 16.29's compiled CSS and in the browser (list, form, report view, dialogs, mobile drawer; light/dark), but not exhaustively: kanban, calendar, gantt, print preview and Link-field dropdowns were not looked at.
- The theme does not change Frappe's icon sprite (one coherent style already).
