# ZatGo Core audit — 2026-10-23

Static audit of `zatgo_core` v0.4.0 at commit `503a098` (60.7k lines of Python, 68 DocTypes, 382 whitelisted
methods), done before any change. Nothing was run during the audit itself; findings that depend on Frappe
internals are marked *(verify)*. The "Status after this round" section at the end says what was fixed, what was
verified, and what is deliberately left.



## Headline
Most of the requested architecture **already existed** (built 2026-10-08 → 10-21). Building a second registry
would have been the wrong move: the upgrade extends what is there, fixes the bugs found in it, and closes the gaps.

| Requested | Already in the repo |
|---|---|

## A. Architecture
- **Package:** `zatgo_core` v0.4.0 (pyproject/`__init__`/hooks agree; `setup.py` says 0.2.2). Requires `erpnext`; relies on Frappe v16 features (Workspace Sidebar, Desktop Icon, `extend_doctype_class`) with no version pin.
- **Modules (`modules.txt`):** ZatGo Core (45 DocTypes), Chat AI (16), Tracker (2), ZatGo Space (5). Industries (restaurant, gym, jewellery, textile) are packages whose DocTypes live in the core module.
- **Layers:** `api/v1/<domain>` (thin, whitelisted) → `services/` → `repositories/` / ERPNext ORM; `events/` (doc hooks), `overrides/` (`extend_doctype_class` mixins), `setup/` (idempotent `ensure_*` run on every migrate), `permissions/`, `industries/`, `plugins/` (config-center registry).
- **Per-site gating model:** zatgo_core is installed on every accounting/van-sale site, so every optional module must be inert unless switched on: hooks go through gated wrappers, Desk JS/CSS is added per request by a `before_request` hook (never `app_include_*`).
- **Desk:** generated "ZatGo" sidebar + one workspace/sidebar/rail icon per app (`ZatGo VanSaleX`, `ZatGo AI`, `ZatGo Tracker`, `ZatGo <Industry>`); SaaS theme (CSS built from partials) switched per site.
- **Dependencies:** `qrcode[pil]`, `anthropic>=1.0` (unpinned), `pypdf`, `python-docx` — all imported (the last three lazily, only by Chat AI).

## B. Existing features that work (preserve)
VanSaleX (orders, invoices, returns, collections, purchases, trips, aging, printing, module/feature access, per-user profiles) · multi-payment allocation · user-wise Sales Invoice naming · narration · IFRS report templates · Source-Warehouse / Payment-Entry-account auto-fill switches · ZATCA Phase-1 QR · idempotent create endpoints (`insert_idempotent`, unique `zatgo_client_id`) · industries layer with server-side gating · Chat AI (local-only by default), Tracker, ZatGo Space as gated modules · SaaS Desk theme + login, EN/AR switcher · App Settings Hub · old-method-path compatibility (`compat_methods.py`, 88 paths). 776 test functions in 56 files.

## C. The existing ZatGo application system

**Registered:** `app_catalog.catalog()` loads `plugins/manifests/core_apps.py` (6 entries) + each `<module>/app_manifest.py`. Manifest keys: `key,label,group,icon,description,switch_field,module_def,workspaces,settings,roles`. A broken module manifest is logged and skipped, never raised.

**Displayed:** hub page (cards by group, switch, settings links) and the generated sidebar: single links first, then one collapsible group per app with a workspace + settings, then a "Settings" group.

**Settings stored:** the on/off state is a Check field per app on **ZG System Settings** (`enable_chat_ai`, `enable_tracker`, `enable_zatgo_space`, `enable_saas_theme`, `enable_language_switcher`, `enable_vansalex_web`; new modules get a hidden Custom Field via `ensure_switch_fields`). Industries: child table `enabled_industries`. App-specific settings live in each app's own DocType (`VanSaleX Settings`, `Chat AI Settings`, `Tracker Settings`, `Space Settings`).

**Enable/disable:** flipping a switch saves ZG System Settings; `on_update` runs `sync_bundled_apps` / `sync_industries` / `sync_core_sidebar`. Off = API answers 404 (`gate_module_api`), module DocTypes are nobody's (`*` permission hooks), hook wrappers return early, Desk entries removed. Data, roles and tables are never touched.

**The four levels (installed / enabled / permitted / feature):**

| Level | Where | Server-enforced? | Gap |
|---|---|---|---|
| Installed | code deployed + Module Def | n/a | external Frappe apps cannot register at all |
| Enabled (site) | switch fields / industries table | **Yes** for bundled modules + industries | **VanSaleX has no site switch**; Delivery/CRM/HR/Warehouse/… API namespaces always on |
| User permitted | Frappe roles/DocPerms | Yes (DocPerms) | no per-app "who may use it" in the manifest; the hub's `roles` key is dead |
| Feature enabled | `vansalex_access` catalog (VanSaleX), Chat AI `enable_*` | Yes for VanSaleX endpoints | catalog is a Python dict mirrored by hand in Dart/JSON/docs |

## D. DocType inventory and naming
- **68 DocTypes, all standard (`custom=0`), none submittable, no duplicate names.** 43 follow `ZG <Name>`; 25 don't: **VanSaleX** (Settings, Access), **Chat AI** (`Chat AI Settings` + 15 `AI …`), **Tracker** (Settings, Activity Session), **Space** (5). **None ends in "ZatGo"** (the historic pattern is gone from this repo).
- Standard ERPNext DocTypes extended: Sales Invoice, Sales Order, Delivery Note, Purchase Receipt/Invoice/Order, Payment Entry, Journal Entry, Mode of Payment, Customer, Item, Account, Company, Warehouse, Supplier, Project/Task/Issue/Timesheet/Employee (Tracker) — via Custom Fields, `doc_events`, `extend_doctype_class`.
- **External wire dependency on non-ZG names: none.** Flutter/SDK/packages/desktop/web never use them on the wire (only comments and one UI string). A rename would be technically feasible, but its blast radius is internal (decision: **keep** — see `naming.md`). Hard-coded name sites, should it ever happen: 28 keys in `hooks.py`, `chat_ai/permissions.py::OWNER_FIELD` (privacy scoping), raw SQL/FULLTEXT in `chat_ai/schema.py`, `ui_apps._ensure_bundled_doctypes`, manifests, `desk_records`, Tracker `_PERM`, JS routes, ~330 test references, and `__Auth` secrets *(verify)*.
- **Other naming inconsistencies (not renamed):** custom-field prefixes `zatgo_*` (28), `custom_*` (17), `custom_zg_*`, `zg_*`, `vansale_*`, `zatca_*`; roles `VanSale User/Admin`, `Delivery`, `Chat AI User/Manager`, `Tracker Top/Sub/Worker` vs `ZG …`; module name "ZatGo Core". `zatgo_client_id` is a wire-protocol name — never touch.
- **Name collision:** the separate `space` app ships its own `Space Plan` / `Space Settings`; the archived `chat-ai`, `tracker`, `zatgo-space` repos carry identical DocType names to the bundled ones (collide if reinstalled on a merged site).
- **Legacy/dead:** `ZG Application Registry` (deprecated, still wired into cache/validation), `ZG Vehicle` (data migrated to ERPNext `Vehicle`, DocType + fleet API remain), `services/jobs.sync_application_registry` (no-op, unscheduled).

## E. Problems by severity
No finding is **Critical** (none gives an unauthenticated caller data or money). Static-only; none exercised at runtime.

**High**

Hub says "System Manager only"; `docs/permissions.md` says Company Admin has no "system" access. | `zg_system_settings.json` perms, `zg_system_settings.py`, `app_hub.py:19` |
| H2 | VanSale field users: module switches don't cover Stock Entry, Payment Entry Pay/Internal Transfer; `transfer` can pull stock from any warehouse; `adjust` unlimited receipt/issue; item-sync books opening stock into a client-chosen warehouse. `ensure_vansale_perms` re-grants removed perms every migrate. | `vansalex_access.check_doc_access`, `api/v1/vansalex/stock.py`, `item_sync_service.py:298`, `setup/ensure_vansale_perms.py` |
| H3 | Chat AI REST/MCP/connector tools call `urllib.urlopen` with no scheme/IP/redirect guard (`file://`, internal addresses); Chat AI Manager can define them. | `chat_ai/core/tool_sources/{rest,mcp,integrations,health}.py` |

**Medium**
- M1 App-registry sync bug: `plugins/discover.py` sends `category: "Core"/"Apps"` but the Select allows only `Operations/Sales/Inventory/HR/Finance/Platform/Other` → the 5 catalog-derived registrations most likely fail validation; the loop swallows the error (verified in code; runtime effect *verify*). It also hard-codes `enabled:1`, `version:"0.1.0"` and overwrites admin edits + appends a history row on every migrate.
- M2 `_normalise` doesn't require `switch_field` for bundled apps, but `zg_system_settings.py:47` and `ui_apps.py:201` index `SWITCH_FIELDS[key]` → one manifest without a switch breaks saving settings and `ensure_ui_apps`.
- M3 Turning the language switcher on from the hub never enables Arabic (only `ensure_ui_apps` on migrate does).
- M4 Two buttons on ZG System Settings ("Clear Core Cache", "Sync Apps") call `zatgo.core.*`, which is defined nowhere → ReferenceError.
- M5 Config API: `seed_bundled_manifests` has no permission check (any user can reset registry rows); `export_settings` and `get_dashboard` open to any user; `save_settings(doctype, values, category)` accepts a caller-chosen `category` and an arbitrary DocType (DocPerms are the only backstop); `can_see_roles` returns True for empty roles and `_load_data` skips read guards; saving company settings flips global `Stock Settings.allow_negative_stock`.
- M6 `ZG Security Settings` has no runtime effect (password rules, 2FA, lockout… are never read); `firebase_credentials_json` is a plaintext `Code` field (audit mixin masks only Password fields).
- M7 Space guest endpoints: sequential-name lookup, unthrottled catalog/usage (N+1), draft orders never expire, non-constant-time token compare.
- M8 Public file upload with client filename and no extension allow-list (item image) → stored XSS vector.
- M9 ~166 mutating endpoints accept GET; most commit inside the handler.
- M10 Trusted client prices (`edit_rate` bypasses sign check; POS and purchase rates unbounded).
- M11 Tracker: `_assign LIKE '%user%'` substring match leaks tasks; `audit.list_for_doc` has no permission check; org-edit not company-scoped.
- M12 `ZG Vehicle` bug: `api/v1/delivery/boys.py:225` validates against `ZG Vehicle`, nulling any ERPNext `Vehicle` name (verified).
- M13 Every migrate overwrites configuration: print formats (8+3 managed, includes customer-specific "Kasib Asia"), Custom DocPerms, registry rows, Desktop Icons (deleted and rebuilt), Space plans. Existing site edits are lost.
- M14 Dangerous tooling: `scripts/fix_controllers.py` and `scripts/generate_doctypes.py` overwrite hand-edited controllers/JSON (e.g. `zg_system_settings.py`) from stale templates.
- M15 `zatgo_client_id` unique index only live-verified for ZG Trip; other doctypes rely on `create_custom_fields` (which this project has seen not alter schema) — verify via `information_schema` on live DBs.
- M16 Performance: unbounded reads (dashboard loads all open invoices 4×; GL ledgers `limit_page_length=0`; `vansalex/admin.py` caps at 5000 trips/invoices → silently wrong totals past the cap), N+1 loops, uncached `vansalex_settings.resolve()` (20–40 queries, called 4–6× per order), missing indexes (`AI Usage Daily`, `AI Chat Message.session`, `ZG Trip` filters, `owner` filters).
- M17 Client-app flags are advisory: `ZG Client Application.enabled`, `block_disabled_clients`, `clients_require_auth` are never enforced server-side; defaults conflict with site switches.

## F. Technical debt
- **Six overlapping "app lists":** `app_catalog`; plugin registry (`ZG Registered Application` + `ZG Setting Section`); client apps (`ZG Client Application`, seeded from hard-coded `constants/client_apps.py`); legacy `ZG Application Registry`; `industries/registry.py`; `api/v1/catalog_data.PRODUCT_CATALOG`. They disagree on names, versions, routes, icons.
- **Duplicated gating:** `bundled_apps.gate_module_api`/`module_*` vs `industries/gate.py`; the industry gate imports a private helper from `bundled_apps`. `industry_api` decorator has no equivalent for sub-apps; VanSaleX uses ad-hoc `require_login()`.
- **Misplaced responsibility:** `switches()` (app state) lives in `services/ui_apps.py`.
- **Hard-coded:** `core_sidebar.ALWAYS_ON_APPS`, hub JS `GROUP_LABELS`, `bundled_apps.DESK_ASSETS`, `_ensure_bundled_doctypes` names, `SINGLE_SETTINGS` allow-list (config API can't reach VanSaleX/Chat AI/Tracker/Space settings).
- **Copy-paste:** `install.after_install` ≡ `after_migrate` (~14 steps); Desk-entry creation implemented 4× (`chat_ai/install.py`, `tracker/install.py`, `industries/sync.py`, `setup/ensure_core_desk.py`); VanSaleX catalog mirrored 4× (Python, profile Select, Dart, docs).
- **Dead/stale:** `ZG Application Registry`, `jobs.sync_application_registry`, `config/docs.py`, `COMPONENT_STORE_DOCTYPE`, `enable_pos`/`kitchen_enabled`/`favorite_apps` (no consumers), empty `workflow/` packages, debug/demo scripts.
- **Missing tests:** plugin registry (zero tests — would have caught M1), non-System-Manager switch attempts, `save_settings` category spoofing, REST-path permission tests for `All` DocTypes, restricted-user tests for reports/portals, migrations, theme behaviour, unique-index coverage. No CI config in the repo.

## G. Security (see E for the ranked list)
Sound and worth keeping: parameterised SQL everywhere (no `eval/exec/subprocess/pickle`), `fetch_url` SSRF pinning, Chat AI owner scoping + local-only guard, confirmation tokens, strict DOMPurify allow-list, idempotent insert with DB-level unique key, random generated passwords in seed code. A prior audit (2026-10-19) fixes are covered by `test_security_hardening.py`. No hard-coded secrets found; `scripts/self_hosted_ai/.env` exists (git-ignored, not read).

## H. Performance (see E-M16)
Switch checks are cheap (cached doc + 6-key dict) but run on every doc event/permission check; `industries.registry.doctype_owner()` rebuilds a dict per call; `boot_session` does ~5 queries per Desk boot; `after_migrate` runs ~16 steps with ≥5 global `clear_cache()` calls and re-registers manifests.

## I. Frontend/UI
Theme: one 238 KB (51 KB gz) un-minified render-blocking CSS, loaded only where switched on; good a11y basics (`:focus-visible`, reduced-motion, forced-colors, touch targets, focus-managed drawer), breakpoints 576/768/992/1200, dark via `[data-theme="dark"]` tokens, thin RTL. The hub page uses inline styles and a hard-coded group-label map and shows no status, version, warnings or errors.
