# ZatGo Core audit — 2026-11-06

Follows `audit_2026-10-23.md`; about 60 commits landed in between (MyBis, Retail/Resto POS, offline sales, Duplicate Prevention, Desk sidebars).

**How it was done.** Code review across security, accounting integrity and quality, then checks on the local bench only: `zg-accounting-test.localhost` (Frappe 16.29, ERPNext 16.31), the full test suite before and after the fixes, and `information_schema` on two local sites. **Production was not touched, so nothing here is confirmed on it.** Nothing has been pushed or deployed.

Each finding is marked:
- **Verified:** seen at runtime on the local bench.
- **Read:** confirmed by reading the code, not run.
- **Reported:** from the review, not independently checked.

## Headline
No finding gives an unauthenticated caller data or money. The most serious problems found:

1. **Delivery could not be completed.** Marking any stop Delivered or Failed through the API always raised an error and saved nothing. Fixed.
2. **Any staff user could close another courier's delivery and set the amount paid,** on sites where they hold write on the DocType. Fixed.
3. **A Resto POS order could be voided while its invoice stayed posted,** leaving revenue and stock booked against a void order. Fixed.
4. **Quotation retries created duplicates,** because the field that idempotency relies on was never created. Fixed.
5. **VAT could silently be left off, or come from an arbitrary template.** Partly fixed; one decision is open (see below).
6. **Seeding VanSale permissions took DocTypes away from every other role,** even System Manager. Fixed; **deploying it restores access, so check who holds those roles first** (see below).

## Decisions for the product owner
1. **Sale with no tax template at all.** A company with no Sales Taxes template still posts invoices with no VAT and no warning. Refusing the sale is the safer rule for a Saudi VAT-registered company, but it would stop sales on any site without a template, and production configuration has not been checked. This was left as it is.
2. **The approved fix was narrowed.** The plan was "configured or default template only". A company with exactly one enabled template still uses it, because there is nothing to guess and refusing could stop live sales. Only several templates with no default are refused.
3. **Who dispatches deliveries?** Completing a stop for a courier through the API now needs both a manager role (System Manager, ZG Company Admin or ZG Branch Admin) and write on the DocType. Assigning needs write on the DocType. Write comes from System Manager, Delivery or a VanSale role. `ZG Company Admin` and `Desk User` do not have it by default, so a dispatcher with only those roles is refused, as they already were on any seeded site. Decide whether a dispatcher role is needed.
4. **ZATCA QR questions, left unchanged because the official text could not be obtained:**
   - Whether tag 3 needs a `Z` or an offset. Server and desktop POS both send local time with no zone; vendor guides disagree.
   - Whether tags 4 and 5 should be in document or company currency on foreign-currency invoices. Only matters for non-SAR invoices.

   Check both against the ZATCA developer portal specification before changing them.

## Open findings

**Medium: security**
- **Offline sales** (*Read*). Where the site policy allows offline, any cashier can send `offline=1` to skip the price floor and discount cap, and back-date up to `max_offline_hours` + 24h. `retail_pos_service.py:240`, `offline_sale.py`. Fix: require a role or a registered device; keep a cap offline.
- **Mutating GET endpoints** (*Reported*: 143 across accounting, tracker, vansalex, `chat_ai`). MyBis keeps GET on purpose (Android 417). Check each client before changing.
- **Plaintext `firebase_credentials_json`** (*Read*, 10-23 M6). A Code field, though the `get_integrations` docstring says secrets are Password fields. No Python reads it, so it may be removable.
- **Space** (*Read*, 10-23 M7). `_assert_internal_token` compares with `!=` and accepts `?token=` in the URL. `get_order` gives guests hostname, desk URL, plan, apps and log stages (no messages), rate limited.
- **Chat AI managers can read every conversation** (*Read*). `chat_ai/api/chat.py::_assert_session_access`.
- **Settings are not company-scoped** (*Read* for the role check). `permissions/guards.py::can_access` checks the role only, so Company and Branch Admins reach any company's settings.
- **POS reads ignore User Permissions** (*Read* for `list_customers`). `resto_pos_admin_service.py:450`.
- **MyBis** (*Read*). `queries.guard` does not handle `if_owner` or query-condition restrictions, so a user limited to their own invoices still gets company totals.
- **Tracker** (*Reported*). `add_member` saves with `ignore_permissions`; `_assign LIKE` substring match; `org_tree` lists all employees when the company is empty; a Team Lead can add an existing non-Employee user to their team.
- **POD OTP is stored but never checked** (*Reported*). `delivery/stops.py`.
- **REST/Desk route around the delivery ownership check** (*Read*). The new check is in the API; `Delivery` and VanSale roles with DocType write can still edit a stop through `/api/resource` or the form.

**Medium: accounting**
- **Replays acknowledge the wrong state** (*Reported*). Sales Order replay acks a cancelled order; return, collection and Stock Entry replays ack any status; the payload is not compared (Retail does compare). `vansalex_service.py:542,861,972,1193,1278`.
- **`client_id` is optional on accounting money endpoints** (*Reported*), so a retried payment can post twice. `create_sales_invoice_from_quotation` has no duplicate check. `erpnext_writes.py:728,882,987,1264`.
- **Sync vs the new same-name block** (*Read*: no sync caller handles `DuplicateRecordError`; effect not run). With the uncommitted `NAME_BLOCK`, an offline-created customer with an existing name would fail on every retry. **Resolve before that work ships.**
- **`sync/batch.py` savepoint rollback after a commit** (*Reported*, effect not run). Each op commits, then a later failure rolls back to a savepoint that may be gone.
- **Stock** (*Reported*). Zero-value receipts distort average cost; driver purchase rate is unbounded; the write-off cap is per line, not cumulative.
- **Submit paths with no rollback** (*Reported*). `create_collection`, `adjust_stock`, `transfer_stock`. Use `submit_or_rollback`.
- **Orphaned Resto invoices may already exist** (not checked). Fix #3 prevents new ones but cannot find old orders voided or left open with a posted invoice. Worth a query per site.

**Low**
Print-time balances from a raw GL sum go stale after back-dating (`events/print_fields.py:101`) · any reader can flip "DUPLICATE COPY" via `trigger_print` (`print_tracking.py:36`) · `get_zatca_qr` writes on a read call · Gym `bill()` leaves a draft with no taxes and a permanent key · a Cash-type return leaves an open credit note with no refund entry · client-ID owner check exists only on the vansalex path · `pos_profile.get` returns company VAT/CR/address to any logged-in user · `ping` exposes the version to guests · Chat AI model endpoints use plain `urlopen` (follow redirects, no IP pinning; admin-set URLs).

- `anthropic>=1.0` has no upper bound.
- About 50 `except Exception: pass` blocks.
- `delivery/stops.py` (591 lines) holds business logic in the API layer. So do parts of `vansalex/orders.py`, `vansalex/admin.py` and `resto_pos/kds_tickets.py`. `api/v1/mybis` is the model to follow.
